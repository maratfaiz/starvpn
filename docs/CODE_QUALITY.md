# Линтеры, типы и тесты

Что настроено, как это запускать и что осознанно оставлено на потом.

---

## Запуск

```bash
# Python
ruff check .                  # линтер — должен быть зелёным
pytest                        # тесты — должны быть зелёными
mypy                          # проверка типов — информационно, см. ниже

# Mini App
cd webapp
npm ci
npm run lint                  # eslint — должен быть зелёным
npm run build:app             # пересборка app.html после правок src/
```

Всё то же самое гоняется автоматически в `.github/workflows/ci.yml` на
каждый push и pull request.

## Ruff

Конфиг — `pyproject.toml`, секция `[tool.ruff]`.

Включён дефолтный набор правил (`E4`, `E7`, `E9`, `F`): он ловит реальные
дефекты — неиспользуемые импорты, необъявленные имена, дубли ключей,
переопределения — и не трогает форматирование.

Осознанно **не** включены:

| Правило | Почему |
|---------|--------|
| `E501` (длина строки) | В коде 691 строка длиннее 100 символов (максимум — 274). Переформатирование дало бы гигантский диff без пользы. Для нового кода ориентир — 120 символов. |
| `E702` (`a = 1; b = 2`) | Сложившийся стиль в хендлерах, ~30 мест. |
| `I001` (сортировка импортов) | Автосортировка переписала бы шапки 56 файлов. Конфиг isort оставлен для точечного `ruff check --select I --fix <файл>`. |

## Mypy

Конфиг — `pyproject.toml`, секция `[tool.mypy]`. Режим прагматичный:
`ignore_missing_imports = true`, аннотации в существующем коде не
требуются.

**В CI mypy не блокирует сборку** (`continue-on-error: true`). Причина —
21 известная ошибка, накопившаяся до появления проверки:

| Категория | Штук | Суть |
|-----------|------|------|
| `arg-type` | 13 | В аргумент, ожидающий `str`/`int`, приходит `object` или `str \| None` — в основном значения из нетипизированных `dict` с тарифами и `marzban_username`, который в модели `Optional`. |
| `operator` | 4 | Арифметика над значениями из тех же нетипизированных словарей. |
| `union-attr` | 3 | Обращение к полям `User` после запроса, возвращающего `User \| None`, без явной проверки на `None`. |
| `assignment` | 1 | Присваивание `dict \| None` переменной, объявленной как `dict`. |

Ни одна из них не приводит к падению в рантайме на текущих данных: везде
значения фактически не `None`. Но это именно долг, а не «ложные
срабатывания» — каждая помечает место, где `None` теоретически пройдёт
дальше по коду.

**Как разгребать:** типизировать словари тарифов (`TypedDict`) — это
закроет `arg-type` и `operator` разом; добавить явные `if user is None:
raise/return` — закроет `union-attr`. После того как счётчик дойдёт до
нуля, убрать `continue-on-error` из `.github/workflows/ci.yml`.

Новые ошибки типов при этом не теряются: вывод mypy виден в логе CI.

## Тесты

`tests/`, запуск через `pytest`. Покрыто то, что можно проверить без
живой БД, Marzban и Telegram:

| Файл | Что проверяет |
|------|---------------|
| `test_init_data.py` | Подпись Telegram `initData` и срок её жизни (защита от replay). |
| `test_branding.py` | Подмена remark в VLESS-ссылке на «STAR VPN», в том числе замена технического `#tg_12345`. |
| `test_marzban_username.py` | Формат Marzban username `{type}_tg_{ident}` и разрешение коллизий. |

`tests/conftest.py` подставляет фиктивные переменные окружения до импорта
модулей бота: `bot.config.Settings` требует их при импорте, иначе pytest
падает ещё на сборе тестов.

Чего пока нет: тестов на хендлеры и эндпоинты — им нужна тестовая БД
(`pytest-asyncio` + поднятый PostgreSQL или SQLite-совместимый слой).
Это следующий логичный шаг.

## ESLint

Конфиг — `webapp/eslint.config.js` (flat config, ESLint 9). Набор узкий:
`js.configs.recommended` плюс правила хуков React. Форматирование не
навязывается, `no-unused-vars` — предупреждение (в JSX хватает намеренно
распакованных пропсов).

## Актуальность `webapp/app.html`

`webapp/app.html` — собранный однофайловый бандл Mini App, он коммитится
в git и именно он отдаётся по `/app` при запуске без Docker.

Автоматизировано с двух сторон:

1. **Прод.** `bot/Dockerfile` собирает Mini App сам (multi-stage: стадия
   `webapp-build` на `node:22`), поэтому образ всегда содержит свежую
   версию независимо от того, что лежит в `app.html`.
2. **Репозиторий.** Job `webapp` в CI пересобирает бандл и сравнивает с
   закоммиченным `app.html`; расхождение — красная сборка с подсказкой
   `cd webapp && npm run build:app`.

Сборка воспроизводима байт-в-байт, поэтому сравнение не даёт ложных
срабатываний.
