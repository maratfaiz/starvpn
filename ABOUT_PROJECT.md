# ABOUT_PROJECT.md — Project Overview: STAR VPN (Sovereign Internet 2026)

## 1. General Concept

STAR VPN — это современный VPN-сервис, интегрированный в экосистему Telegram
(Bot + Mini App) и с полноценным веб-личным кабинетом на сайте. Проект
ориентирован на обход продвинутых систем DPI и обеспечение максимальной
приватности в условиях 2026 года.

## 2. Technical Core

- **VPN Engine**: Marzban (Xray-core).
- **Primary Protocol**: VLESS + Reality. Это критически важно: мы используем
  технологию заимствования TLS-рукопожатия (от популярных ресурсов, таких как
  Google или Microsoft), чтобы трафик выглядел как легитимный HTTPS.
- **Zero Logs Strategy**: конфигурация Xray должна исключать любые логи
  доступа. Параметры `access` и `error` в LogObject должны быть установлены в
  `"none"`, а `loglevel` — в `"none"`.

## 3. Technology Stack

- **Backend**: Python 3.11+, aiogram 3.x (асинхронный фреймворк для бота) и
  FastAPI — в одном процессе, см. `README.md`.
- **Database**: PostgreSQL 16 + SQLAlchemy 2.0 (async), миграции — Alembic.
- **Frontend**: сайт (`landing/`) и админка (`admin/`) — статичный
  HTML/CSS/vanilla JS без сборки; Telegram Mini App (`webapp/`) — React +
  Vite + Tailwind, единственная часть, которую нужно собирать.
- **Integration**: взаимодействие с Marzban через REST API.
- **Infrastructure**: Docker Compose (сервисы `db` + `bot`, см. `README.md`);
  Marzban разворачивается отдельно, не через compose этого репозитория.

## 4. Business Logic & Features

- **Auto-Trial**: при первом запуске бота (`/start`) пользователь
  автоматически получает временный доступ на `TRIAL_DAYS` дней (по умолчанию
  **2 дня**, настраивается через `.env`) через API Marzban. Выдаётся один раз
  на `telegram_id` (`User.trial_used`).
- **Referral System (2+1)**: за каждых двух активных рефералов (купивших
  подписку) пригласивший получает +30 дней к своему тарифу. Логика
  отслеживается в БД через `referrer_id`. Есть отдельное предложение по
  упрощению системы (сейчас складывается ещё и разовые бонусы-достижения) —
  не принято, см. `AGENTS/architecture/referral-system.md`.
- **Payments** (актуально на 2026-08-31 — тумблеры и провайдеры менялись
  много раз, при сомнении сверяйся с `CLAUDE.md` → "Payment methods" и
  `AGENTS/architecture/purchase-flow.md`, а не с этим разделом):
  - **Сайт** (`/account`, `/get-vpn`): оплата картой (Robokassa) или
    криптовалютой. Telegram Stars на сайте не существует в принципе — это
    нативная валюта Telegram Payments API, вне клиента Telegram не работает.
  - **Telegram Mini App** (`webapp/`): Telegram Stars (основной способ) и
    оплата картой (Robokassa). Криптовалюта в интерфейсе Mini App не
    реализована.
  - **Telegram-бот** (классический чат-флоу, `bot/handlers/`): Stars, карта и
    криптовалюта — все три доступны и включаются/выключаются тумблерами из
    админки.
  - Никакого отдельного провайдера Prodamus или YooMoney в проекте больше
    нет — оба использовались на более ранних этапах и были полностью выведены
    из кода (см. ADR-015 в `AGENTS/decisions/ADR.md`). Не добавляй их обратно
    по этому файлу — если он на момент чтения снова расходится с кодом,
    доверяй коду и `CLAUDE.md`.

## 5. UI/UX Requirements

- **Haptic Feedback**: каждое ключевое действие в Mini App (оплата, включение
  VPN, ошибка) должно сопровождаться тактильной отдачей через `@tma.js/sdk`.
- **Theme Sync**: интерфейс должен автоматически подстраиваться под цветовую
  схему Telegram (Dark/Light).

## 6. Project Structure (Monorepo)

- `/bot` — логика Telegram-бота и FastAPI backend: хендлеры, мидлвари,
  ORM-модели, бизнес-логика.
- `/webapp` — исходный код Mini App (React).
- `/landing`, `/admin` — сайт и веб-админка (статичный HTML/CSS/JS).
- `/alembic` — миграции БД.
- `/infra` — Docker-конфигурации, скрипты деплоя, конфиги Xray.
- `/.env` — все секреты (Bot Token, Marzban API Key, DB Credentials) — никогда
  не коммитится в git.

Актуальная и более подробная карта репозитория — в `README.md`.

## 7. Веб-аккаунт — второй способ подключиться (backend реализован)

Личный кабинет на сайте (`/login`, `/account`) — полноценная альтернатива
Telegram, а не разовая покупка без возможности потом зайти. Актуально в
первую очередь для пользователей, которым сам Telegram недоступен без VPN.

Вход — email + пароль (без Telegram): `POST /api/account/register` создаёт
аккаунт и шлёт код подтверждения на почту, `POST /api/account/verify-email`
подтверждает код и ставит cookie-сессию (`star_session`, 30 дней);
`POST /api/account/login` — вход уже зарегистрированным email+паролем.

Реализовано без изменения существующей схемы: `User.telegram_id` остался
`NOT NULL` (не стал опциональным, как планировалось изначально) — веб-аккаунту
при первом входе присваивается синтетический отрицательный `telegram_id`
(реальные Telegram ID всегда положительные, коллизий не бывает). Поэтому
устройства, платежи, рефералка и вся остальная логика, завязанная на
`users.telegram_id`, работают для веб-аккаунтов без единой строчки изменений.
Проверка "привязан ли реальный Telegram" — `user.telegram_id > 0`.

Ещё не реализовано: привязка существующего Telegram-аккаунта к уже
созданному веб-аккаунту (сейчас это два независимых `User`, если один и тот
же человек регистрируется и через бота, и через email) — это отдельная
будущая задача, не блокирующая текущий функционал.

Личный кабинет (6 вкладок: Подписка/Устройства/Продление/Приглашения/
Подарить/Профиль) — фронтенд на `/account`, стиль как у остальных статичных
страниц сайта (`landing/`, без билд-степа).
