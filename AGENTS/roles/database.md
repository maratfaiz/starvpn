# Роль: Database

> Ты отвечаешь за схему данных: таблицы, связи, миграции.

## Зона ответственности

| Папка | Что это |
|---|---|
| `bot/models/` | SQLAlchemy 2.0 async ORM-модели |
| `alembic/versions/` | Миграции — единственный правильный способ менять схему боевой БД |
| `alembic.ini`, `alembic/env.py` | Конфиг Alembic |

## Golden rule

**Меняешь схему — сначала пишешь Alembic-миграцию, потом код.** Никогда
не наоборот, никогда не через ручной `ALTER TABLE` на проде.

```bash
alembic revision -m "краткое описание" # создать файл миграции
# → вручную дописать upgrade()/downgrade() в alembic/versions/000X_*.py
alembic upgrade head # применить локально/на сервере
```

На **новом** окружении `Base.metadata.create_all()`
(`bot/utils/database.py`) создаёт схему автоматически при первом
старте — Alembic обязателен только когда меняешь схему **уже
существующей боевой базы** (иначе `create_all()` не подхватит
изменения существующих таблиц).

## Важные особенности схемы (не "чини", это осознанно)

- **`users.telegram_id` — `NOT NULL`, не nullable.** Веб-аккаунты (только
 email, без Telegram) получают **синтетический отрицательный**
 `telegram_id`, а не `NULL` — так все таблицы, у которых внешний ключ на
 `users.telegram_id` (`Device`, `Payment`, `GiftNotification`,
 рефералка), работают одинаково для Telegram- и веб-аккаунтов без
 изменений схемы.
- Индексируй каждый внешний ключ и часто запрашиваемую колонку
 (правило из `CLAUDE.md`).
- Только `AsyncSession` — никаких синхронных сессий в новом коде.

## Что можно

- Добавлять новые таблицы/колонки под задачу (через миграцию).
- Оптимизировать запросы, добавлять индексы.

## Что нельзя

- Делать `telegram_id` nullable — сломает FK-логику веб-аккаунтов
 (см. выше).
- Ручные `ALTER TABLE`/прямой SQL по боевой БД в обход Alembic.
- Удалять/переименовывать существующие колонки без плана миграции
 данных — на проде есть реальные пользователи.

## Ключевые файлы

`bot/models/user.py` (центральная модель), `bot/utils/database.py`
(инициализация БД), `bot/utils/webauth.py` (логика синтетического
`telegram_id` для веб-аккаунтов — `_get_or_create_user_by_email`).

См. также [`AGENTS/architecture/database.md`](../architecture/database.md)
для полной схемы таблиц и связей.
