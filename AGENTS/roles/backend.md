# ⚙️ Роль: Backend

> Ты пишешь бизнес-логику, API-эндпоинты и всё, что происходит на
> сервере в ответ на запрос.

## Зона ответственности

- `bot/api.py` — FastAPI-приложение: `/api/*` (публичное API для сайта/Mini App),
  `/web/*` (API админки), раздача HTML (`_serve_html`).
- `bot/utils/` — интеграции: Marzban-клиент, платёжные провайдеры,
  почта, генерация QR, настройки.
- `bot/middlewares/` — общая логика на каждый запрос (например, бан-чек).

## Важно понимать про архитектуру

Backend и Telegram-бот — **один процесс**, не два сервиса. `bot/main.py`
запускает aiogram (long polling) и uvicorn (FastAPI) одновременно через
`asyncio.gather`, в одном event loop. Это значит:

- Не создавай отдельный сервис/контейнер для API — он уже есть, это тот же `bot`.
- Общий код (модели, утилиты) между ботом и API — переиспользуй, не дублируй.

## Identity: два способа входа, один резолвер

У пользователя может быть Telegram-сессия (Mini App, заголовок
`X-Telegram-Init-Data`) **или** веб-сессия (cookie `star_session`, вход
по email-ссылке). Для эндпоинтов, которые должны работать в обоих
случаях, используй `_resolve_tg_id(request, x_telegram_init_data, session)`,
**не** `_tg_id(x_telegram_init_data)` напрямую — последний работает
только для Mini App и уже был причиной бага (`/api/gift/pending` не
работал для веб-аккаунтов, пока не переключили резолвер).

```python
# ✅ Правильно — работает для Mini App и веб-аккаунта
tg_id = await _resolve_tg_id(request, x_telegram_init_data, session)

# ❌ Только Mini App, сломает веб-аккаунты
tg_id = _tg_id(x_telegram_init_data)
```

Веб-аккаунты (только email, без Telegram) получают **отрицательный**
`telegram_id` — реальные Telegram ID всегда положительные, коллизий не
бывает. Проверка "это настоящий Telegram-аккаунт?" — `user.telegram_id > 0`.

## Что можно

- Добавлять новые `/api/*` эндпоинты под задачу.
- Расширять существующие модели полями (через Alembic-миграцию, см.
  `database.md`).
- Рефакторить бизнес-логику, если не меняется контракт (что принимает/
  отдаёт эндпоинт), без явного согласования.

## Что нельзя

- 🚫 Заводить параллельный `/api/account/*`-эндпоинт, дублирующий
  `_resolve_tg_id`-логику — расширяй общий резолвер, а не копируй его.
- 🚫 Менять формат Marzban-логина (`tg_{telegram_id}` / `web_{id}`).
- 🚫 Отключать/ослаблять проверку подписи платёжных вебхуков.
- 🚫 Писать `print()` — только `logging` (см. `CLAUDE.md`).
- 🚫 Синхронные SQLAlchemy-сессии — только `AsyncSession`.
