# Newbie.md — подробная инструкция для первого входа

Этот файл — дополнение к [`new_agent.md`](./new_agent.md). Если тот файл —
"правила игры", то этот — "как сделать первый ход".

---

## Шаг 0 — ты прочитал new_agent.md?

Если нет — вернись и прочитай. Здесь предполагается, что базовый контекст
и красные линии уже усвоены.

---

## Шаг 1 — определи, кто ты

Прежде чем трогать хоть один файл, ответь себе на вопрос: **какая роль
описывает задачу, которую тебе дали?**

```
                    ┌───────────────────────────────┐
                    │   Какая у меня задача?         │
                    └───────────────┬─────────────────┘
                                    │
      ┌──────────────┬─────────────┼─────────────┬──────────────┬──────────────┐
      ▼              ▼             ▼             ▼              ▼              ▼
 "Поправь верстку  "Баг в API /   "Новая логика   "Правка текста  "Проблема с    "Всё падает,
  сайта/страницу"   бот не         бота, хендлер"  бота/уведом-    базой/         не деплоится"
                    отвечает"                       ления"         миграция"
      │              │             │             │              │              │
      ▼              ▼             ▼             ▼              ▼              ▼
 frontend.md     backend.md    backend.md      bot.md        database.md    devops.md
                                                                              (или qa.md,
                                                                          если это баг,
                                                                          а не деплой)
```

Если задача — **макет, цвета, UX** (не код, а то, "как должно выглядеть") —
это `designer.md`. Если задача — **найти баг, проверить, что ничего не
сломалось** — это `qa.md`.

Одна задача может касаться двух ролей (например, "добавь кнопку в бот и
API под неё") — это нормально, просто прочитай обе инструкции.

| Роль | Файл | Когда это ты |
|---|---|---|
| Дизайнер | [`roles/designer.md`](./roles/designer.md) | Макеты, UI/UX, визуальный язык, но не сам код страниц |
| Frontend | [`roles/frontend.md`](./roles/frontend.md) | `landing/`, `admin/`, `webapp/` — вёрстка, JS, стили |
| Backend | [`roles/backend.md`](./roles/backend.md) | `bot/api.py`, бизнес-логика, эндпоинты |
| Bot | [`roles/bot.md`](./roles/bot.md) | `bot/handlers/`, диалоги и команды в Telegram |
| Database | [`roles/database.md`](./roles/database.md) | `bot/models/`, `alembic/`, схема БД |
| DevOps | [`roles/devops.md`](./roles/devops.md) | `infra/`, деплой, Docker, сервер |
| QA | [`roles/qa.md`](./roles/qa.md) | Поиск багов, проверка регрессий, тестирование |

## Шаг 2 — прочитай инструкцию своей роли

Открой `AGENTS/roles/<твоя-роль>.md`. Там: зона ответственности, что можно
и что нельзя именно тебе, с какими файлами обычно работаешь.

---

## Шаг 3 — не лезь в чужую зону без необходимости

Ты дизайнер, а задача требует поправить SQL-запрос в `bot/api.py`? Значит
задача на самом деле для двух ролей — либо ты сам временно переключаешься
в контекст `backend.md` (и говоришь об этом явно в `Agents_history.md`),
либо честно говоришь, что часть задачи не в твоей зоне.

Это не бюрократия ради бюрократии — а способ не наступать друг другу на
ноги, когда несколько агентов работают над одним репозиторием параллельно
(что уже случалось, см. пример в `Agents_history.md`).

---

## Шаг 4 — посмотри архитектуру, если задача не тривиальна

Перед серьёзными изменениями — загляни в `AGENTS/architecture/`:

- [`overview.md`](./architecture/overview.md) — как части системы связаны между собой
- [`database.md`](./architecture/database.md) — схема БД, таблицы, связи
- [`api.md`](./architecture/api.md) — список эндпоинтов и кто их вызывает

Если твоё изменение выглядит как **архитектурное решение** (новая
таблица, новый способ авторизации, смена библиотеки) — после реализации
добавь запись в [`decisions/ADR.md`](./decisions/ADR.md).

---

## Шаг 5 — сделай задачу

Следуй правилам из `new_agent.md`. Проверяй себя: линтер, синтаксис,
ручной прогон там, где возможно.

---

## Шаг 6 — обязательно оставь запись в Agents_history.md

Это последний и обязательный шаг. Без него следующий агент (человек или
ИИ) не будет знать, что ты сделал и почему. Формат — в самом файле
[`Agents_history.md`](./Agents_history.md).

## Частые ошибки новичков (по опыту предыдущих агентов)

- Не читать `CLAUDE.md`/`README.md` перед началом — потом переделывать.
- Переименовывать папки "для порядка", не проверив все места, где путь захардкожен (Dockerfile, docker-compose.yml, импорты Python).
- Чинить симптом вместо причины (например, обходить ошибку вместо того, чтобы понять, откуда она).
- Не оставлять запись в `Agents_history.md` — следующий агент тратит время на то, чтобы заново понять, что уже сделано.
- Работать параллельно с другим агентом над тем же файлом без координации через `Agents_history.md`.
