#  new_agent.md — обязательно к прочтению

> Если ты агент (Claude, ChatGPT, любая ИИ-модель) и тебя только что подключили
> к этому проекту — **прочитай этот файл целиком, прежде чем менять хоть одну строку.**
> Это не пожелание, это условие входа.

---

## 1. Краткий контекст проекта

**STAR VPN** — Telegram-нативный VPN-сервис: бот + сайт + Mini App + админка.

| | |
|---|---|
| Продукт | VPN на протоколе **VLESS + Reality** (обходит блокировки, маскируется под обычный HTTPS) |
| Принцип | **Zero Logs** — IP, трафик и история подключений нигде не пишутся |
| Вход для юзера | Telegram-бот (`@starisvpnbot`) + сайт `starvpnservice.ru` (для тех, у кого нет доступа к Telegram) |
| Архитектура | **Один процесс** — aiogram-бот и FastAPI живут в одном `bot/main.py`, один Docker-контейнер |
| Сайт/админка | Обычный HTML/CSS/vanilla JS, без сборки — правишь файл напрямую |
| Mini App | React, **единственная часть, которую нужно собирать** (`npm run build:app`) |
| Оплата | Telegram Stars, Robokassa, ЮMoney (крипта скрыта из UI, но код не удалён) |
| Данные | PostgreSQL + SQLAlchemy 2.0 async, миграции — Alembic |

Полная бизнес-логика — в [`ABOUT_PROJECT.md`](../ABOUT_PROJECT.md).
Технические правила и стиль кода — в [`CLAUDE.md`](../CLAUDE.md).
Как реально устроен код (карта репозитория) — в [`README.md`](../README.md).

Это **боевой продукт с реальными платящими пользователями**, не учебный проект.
Ломать прод, если оно уже работает — самая дорогая ошибка, которую можно
здесь совершить.

## 2. Что нельзя трогать

Это красные линии. Не "лучше спросить", а **нельзя без явного запроса
человека**:

| Что | Почему |
|---|---|
| `infra/xray_config.json` → менять `access`/`error`/`loglevel` на что-то кроме `"none"` | Это Zero Logs — юридическое и репутационное обещание продукта |
| Формат Marzban-логина `tg_{telegram_id}` / `web_{id}` | Меняешь — ломаешь связь всех существующих пользователей с их VPN-аккаунтами |
| Проверку подписи вебхуков (Robokassa MD5, ЮMoney SHA-256) | Отключишь — любой сможет подделать "оплату" |
| Стек технологий (см. таблицу в `CLAUDE.md`) без обсуждения | Он зафиксирован осознанно |
| Прямой SQL/ручные миграции по боевой БД | Только через Alembic (`alembic/versions/`) |
| Массовое переименование/перенос папок без ADR | Ломает Docker build context, импорты, деплой — см. `AGENTS/decisions/ADR.md` |
| Коммит `.env`, ключей, паролей | Секреты — только в `.env`, никогда не в git |
| Визуальный дизайн сайта "по вкусу" | Дизайн приходит из готовых макетов/дизайн-системы — не изобретай свою |
| Работа в зоне другой роли без необходимости | См. `AGENTS/roles/` — у каждой роли своя территория |

Если задача требует нарушить что-то из списка — **остановись и спроси
человека**, а не решай сам.

## 3. Правила

1. **Сначала пойми контекст, потом пиши код.** Прочитай `CLAUDE.md`,
 `README.md` и релевантный `AGENTS/roles/*.md` перед первым коммитом.
2. **Определи свою роль** — см. [`Newbie.md`](./Newbie.md). Без роли не
 понятно, что твоё, а что чужое.
3. **Один агент — один PR/фича за раз.** Не пытайся переписать полпроекта
 в один заход "чтобы было лучше".
4. **Не изобретай архитектуру заново.** Если что-то кажется странным —
 сначала проверь `AGENTS/decisions/ADR.md`: возможно, так сделано
 осознанно и есть причина.
5. **Не удаляй чужой код "на всякий случай".** Не уверен, что что-то не
 используется — проверь через поиск по репозиторию, а не удаляй вслепую.
6. **Дизайн и бизнес-логика — не одно и то же.** Можно чинить бэкенд-баг
 без изменения интерфейса; можно менять вёрстку, не трогая API.
7. **Флагуй несостыковки, а не чини их молча.** Если макет/задача
 противоречит тому, что реально есть в коде — скажи об этом явно, не
 додумывай за пользователя.
8. **После работы — обязательно запись в [`Agents_history.md`](./Agents_history.md).**
 Кто ты, что сделал, что важно знать следующему агенту. Без этого шага
 задача не считается завершённой.
9. **Проверяй перед тем как сказать "готово".** Синтаксис, линтер, ручной
 прогон — по возможности. "Наверное сработает" — не готово.
10. **Если что-то ломает прод — это стоп-сигнал**, а не "доделаю потом".
 Останавливайся и чини корень проблемы.
