# Purchase Flow — как пользователь покупает подписку

Два независимых пути. Оба ведут к одному и тому же результату — продлению
`User.subscription_expires_at` и (для устройств) выдаче VLESS-ключа в
Marzban — но через разные экраны и разные способы идентификации.

```

                         └──────────────┬────────────┘
                                        │
                       ┌────────────────┴────────────────┐
                       ▼                                  ▼
                ┌──────────────┐                 ┌──────────────────────┐
                │  Telegram-бот │                 │  Сайт (обязательна    │
                │  (initData)   │                 │  регистрация — email  │
                │               │                 │  или Telegram OIDC)   │

                       │                                      │
```

## Ключевой момент: на сайте оплата требует аккаунта (ADR-013)

`/get-vpn` — 3 шага: **Тариф → Аккаунт → Оплата**. Шаг "Оплата" заблокирован
(`.locked`/`pointer-events:none`), пока `GET /api/me` не подтвердит сессию:

1. Пользователь без Telegram выбирает тариф на `/get-vpn`.
2. Не залогинен → выбранный тариф сохраняется в
   `localStorage['star_vpn_pending_purchase']`, пользователь уходит на
   `/login` (регистрация email+пароль с подтверждением кодом, либо вход
   через Telegram OIDC — см. `AGENTS/decisions/ADR.md` ADR-006/ADR-007).
3. После входа/регистрации — `/account`, вкладка "Продление" (открывается
   автоматически, `resumePendingPurchase()` подхватывает сохранённый
   тариф): выбор способа оплаты (карта или крипта) →
   `/api/invoice/{provider}` создаёт счёт → пользователь платит у
   провайдера → вебхук провайдера продлевает подписку на `User`,
   привязанном к его аккаунту.

**Старый гостевой путь без регистрации** (`/api/guest/*`, `GuestOrder`,
`card-success.html`'s `pollGuestOrder`) технически всё ещё существует и
работает — просто `/get-vpn` на него больше не ссылается с тех пор, как
регистрация стала обязательной (ADR-013). Если где-то остался прямой
линк на него в обход `/get-vpn`, он продолжит работать без регистрации.

## Способы оплаты — кто где

| Канал | Способы | Управление |
|---|---|---|
| Telegram-бот, классический чат-флоу (`bot/handlers/payment.py` и др.) | Stars, карта (Robokassa), крипта (CryptoPay) | Тумблеры в `app_settings` (`bot/utils/settings_store.py`), редактируются в админке → Настройки |
| Telegram Mini App (`webapp/`, `RenewSheet.jsx`) | Stars (основной способ), карта — крипта в интерфейсе Mini App **не реализована** (не бэкенд-ограничение, просто нет UI-варианта) | Тумблер stars/card |
| Сайт, есть аккаунт (`/account`, `/get-vpn`) | карта, крипта — Stars **не** предлагается (нативная валюта Telegram, вне сайта не работает) | Те же тумблеры |
| Сайт, гость (`/api/guest/*`, сейчас нигде не заходит из `/get-vpn`) | только карта — крипта и Stars недоступны в принципе (архитектурно, `guest_checkout` их не принимает) | Тумблер card |

На 2026-08-30 (ADR-014/ADR-015): card, crypto и stars включены. ЮMoney,
который раньше был вторым рублёвым способом оплаты рядом с картой, —
**удалён насовсем**, а не выключен тумблером: кода, эндпоинтов и
пункта в админке для него больше нет. Если понадобится второй
рублёвый провайдер — его нужно строить заново.
