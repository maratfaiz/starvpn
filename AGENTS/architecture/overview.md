# 🏗️ Architecture Overview

## Один процесс — не микросервисы

```
                         ┌───────────────────────────────┐
                         │     bot/main.py (1 процесс)    │
                         │                                │
   Telegram ──polling──▶ │   aiogram-бот  +  FastAPI      │ ◀── Netlify (TLS/домен) ── браузер
                         │              (uvicorn :8080)    │
                         └───────────────┬────────────────┘
                                         │ читает файлы с диска
                    ┌────────────────────┼────────────────────┐
                    ▼                    ▼                    ▼
              landing/*.html       admin/index.html      webapp/app.html
              (сайт, отдаётся       (админка,             (Mini App,
               как есть)            отдаётся как есть)    собранный React)
                                         │
                                         ▼
                              ┌────────────────────┐
                              │   PostgreSQL 16     │
                              └────────────────────┘
                                         │
                                         ▼
                              ┌────────────────────┐
                              │  Marzban / Xray-core │  ← отдельно, не в этом compose
                              │  (VLESS + Reality)   │
                              └────────────────────┘
```

## Почему так, а не микросервисы

Продукт достаточно небольшой, чтобы разделение на сервисы добавляло
только операционную сложность (несколько деплоев, сетевые вызовы между
сервисами, отдельные логи) без реальной выгоды. Один процесс = один
контейнер = один `git pull` + рестарт применяет все изменения сразу.
См. `AGENTS/decisions/ADR.md` → "ADR-001".

## Два входа для пользователя

```
                    ┌─────────────────────────┐
                    │   Как пользователь       │
                    │   попадает в систему?    │
                    └────────────┬─────────────┘
                                 │
                 ┌───────────────┴────────────────┐
                 ▼                                 ▼
        Telegram Mini App                    Сайт (браузер)
        X-Telegram-Init-Data                 cookie star_session
        (реальный telegram_id > 0)           (email, магик-линк)
                 │                                 │
                 └───────────────┬────────────────┘
                                 ▼
                     _resolve_tg_id(request, initData, session)
                                 │
                                 ▼
                    один и тот же User в БД,
                    одни и те же Device/Payment/рефералка
```

Веб-аккаунт без Telegram получает **синтетический отрицательный**
`telegram_id` — поэтому вся остальная схема БД (внешние ключи на
`users.telegram_id`) работает одинаково для обоих случаев без изменений.
Подробности — `AGENTS/architecture/database.md`.

## Три раздела сайта, три разных типа обслуживания

| Раздел | Тип | Собирается? |
|---|---|---|
| `landing/` (сайт), `admin/` (админка) | Статичный HTML/CSS/JS | Нет — читается с диска налету |
| `webapp/` (Mini App) | React SPA | Да — `npm run build:app` → `webapp/app.html` |
| `bot/` (backend + бот) | Python/FastAPI/aiogram | Docker-образ, `bot/Dockerfile` |
